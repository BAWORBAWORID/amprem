# Capitalization

Rules for consistent capitalization in UI and documentation.

## Sentence case (Default)

Use sentence case for almost everything:

- Headings and titles
- Button labels
- Menu items
- Column headers
- Tooltips
- Error messages
- Empty states

**Sentence case**: Capitalize only the first word and proper nouns.

- ✅ "Save your changes"
- ❌ "Save Your Changes"
- ✅ "Create new workspace"
- ❌ "Create New Workspace"

## Proper nouns (Always Capitalize)

- Product names and brand names
- Feature names when trademarked
- Company names
- People's names and titles when used with names

## Common nouns (Lowercase)

General concepts and categories:

- ✅ workspace, dashboard, pipeline, settings, project
- ❌ Workspace, Dashboard, Pipeline, Settings, Project

Exception: Capitalize when starting a sentence.

## UI elements

When referring to UI elements by their label:

- ✅ "Select the **Save** button"
- ✅ "In the **Settings** pane"
- Use bold for the UI element name, match its actual capitalization

## After colons

| What follows | Capitalization | Example |
|--------------|----------------|----------|
| Complete sentence | Capitalize | "One main benefit: It reduces latency." |
| Fragment or phrase | Lowercase | "One main benefit: reduced latency." |
| Proper noun | Capitalize | "One platform: GitHub." |

## Don'ts

- ALL CAPS for emphasis (use bold instead)
- Title Case for UI text
- Capitalizing common nouns for importance
